# Legal and data-lifecycle design register

This register tracks engineering choices and operator facts without deciding whether a law applies to every Sierx deployment.

| Topic | Current state | Decision owner / evidence needed |
|---|---|---|
| Current audience | Public signup is absent; the current instance is described by its owner as private to the owner. | Instance operator verifies the deployed access policy. |
| Public admission and children | `SIERX_REGISTRATION_MODE` defaults to `private`; `invitation` and `public` are explicit reserved modes that fail startup. Signup, age-screening, actual-knowledge response, parent access/deletion and verified consent are not implemented. | Product owner and applicable legal review before enabling any admission flow; required controls need code and acceptance evidence first. |
| Email | No email sender or notification-delivery path is present; no SMTP or commercial mail provider is contacted by the app. | Product owner defines purpose/preferences/transport before future implementation. |
| Billing | No billing/subscription routes, dependencies or payment provider integration is present; no paid subscriptions are planned. | Revisit only if the product scope changes. |
| Privacy notice | Public route is backed by instance environment settings and reports setup as incomplete when operator/contact/retention/backup/service/version/date facts are missing. The page describes account, authentication, content/history, preferences, logs, rate-limit data and the limits of soft deletion. | Each instance operator supplies and verifies the facts before serving others. Do not treat the app notice as legal advice. |
| External resources and source secrets | HTML asset validation rejects remote auto-loaded resources while allowing ordinary external links; runtime browser observation and a redacted secret-pattern gate are being added to the automated aggregate. Initial scan at baseline `da92cbb890d69d982ee4586046b5ede672c26eb4` found no high-confidence credential patterns in 413 working-tree files or 838 distinct text source blobs reachable from local Git refs. | The scan is bounded and does not replace repository-host secret protection or operator credential controls. Re-run against the final pushed revision and review any host-side history outside these local refs. |
| Copyright notice | Public route exists, but agent/contact/notice/counter-notice/repeat-infringer values are instance-specific and remain unconfigured until supplied. | Relevant instance operator determines applicability, registration, and process. |
| Content lifecycle | History retains old/new values; soft deletion is not erasure; schema says no pruning. No supported application or operator-tool workflow yet provides data export, correction, redaction, legal holds, account deactivation with session revocation, or erasure-aware restore. | Keep disclosures limited to current behavior. Product owner and operator must approve lifecycle rules before destructive/redaction tooling or any retention promise. |
| RLS and database roles | Authenticated API requests establish transaction-local workspace, user and role context. Migration 0011 enables and forces tenant policies, separates runtime/auth/maintenance roles, limits auth-secret columns, and has catalog/direct-SQL proofs. | Engineering proof is in the repository gates; deployment operators still provision distinct credentials and verify their database targets and grants. |
| Accessibility | Purpose-specific initial titles and legal/footer surfaces are implemented. Existing automated browser tests cover keyboard workflows and route/theme behavior. Full WCAG 2.1 AA evidence still requires manual screen-reader, reflow, focus and announcement review. | Product owner records manual review results and remaining defects; automated checks are not certification. |
| Hosted release and recovery | Offline promotion, rootless installer, Rocky host, encrypted off-machine restore, and two-release rollback require runtime/operator evidence. | Operator and release maintainers provide exact-candidate and host evidence. |

Do not mark Phase 2 accepted from this register alone. See `docs/PHASE-2-ACCEPTANCE.md` for the release and human exit gates.
